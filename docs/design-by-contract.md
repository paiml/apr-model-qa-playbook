# Design by Contract: APR Model Qualification

## Overview

The APR Model QA Playbook system applies Design by Contract (DbC) principles to
model qualification. Every model accepted into the APR ecosystem must satisfy a
formally specified contract: the **Model Qualification Score (MQS)**.

MQS is not a soft heuristic. It is a weighted, gate-guarded composite score where
P0 gateway failures zero the entire score. The contract is: a model either meets
MQS threshold (default 85) or it is rejected.

## Gateway Checks: G0-G4

Gateway checks are hard preconditions. If any G-level check fails, the MQS score
is forced to zero regardless of all other results. They enforce the invariant that
a model is minimally functional before quality measurement begins.

| Gate | Name             | Precondition                          | Severity |
|------|------------------|---------------------------------------|----------|
| G0   | DIM-SMOKE        | Config dimensions match architecture  | P0       |
| G1   | LOAD             | Model loads within timeout (<60s)     | P0       |
| G2   | INFER            | Basic inference produces output        | P0       |
| G3   | STABLE           | No panics or crashes during execution  | P0       |
| G4   | VALID            | Output is not garbage                  | P0       |

G0 is metadata-only (no inference required, completes in ~2-5 seconds). G1-G4
require actual model loading and inference. This two-phase design enables fast
rejection of obviously broken models before expensive GPU time is consumed.

## Falsification Gates

Beyond gateways, playbooks define **falsification gates** organized by category.
These are Popperian: the goal is to falsify the model's fitness, not to confirm it.

| Category      | Prefix    | Weight | Examples                                    |
|---------------|-----------|--------|---------------------------------------------|
| Quality       | F-QUAL    | 30%    | Arithmetic accuracy, code syntax validity   |
| Performance   | F-PERF    | 25%    | Tokens/sec threshold, time to first token   |
| Stability     | F-STAB    | 20%    | Deterministic output, no memory leaks       |
| Compatibility | F-COMP    | 15%    | All formats work, all backends pass         |
| Edge Cases    | F-EDGE    | 10%    | Empty prompt, unicode, max token limit      |

Additional specialized gate families exist for format validation (F-APR-FORMAT),
differential testing (F-ROSETTA), profiling (F-PROFILE-CI), and trace payload
verification (F-TRACE-PAYLOAD).

Across 173 model playbooks and 4 example playbooks, the system defines 28 unique
gate IDs reused across models. Total gate instances (counting per-playbook usage)
scale with the model registry.

## Severity Levels

- **P0 (Blocker)**: Gateway failures. Zero the MQS score. Pipeline stops immediately
  under `stop_on_p0` failure policy (Jidoka principle).
- **P1 (Must-Fix)**: Quality, performance, stability, and compatibility gates.
  These contribute to the weighted MQS score. A model can pass with P1 failures
  but will receive a lower grade.
- **P2 (Nice-to-Have)**: Edge case and regression gates. Contribute to score but
  do not block certification at MVP tier.

## Two-Tier Certification

| Tier | Requirements                     | Use Case                        |
|------|----------------------------------|---------------------------------|
| MVP  | G0-G4 pass + basic inference     | Fast smoke qualification        |
| Full | All gates pass, MQS >= 85        | Production certification        |

Certifications are stored in `certifications/` (73 models certified). Each
certification directory contains evidence artifacts: JUnit XML, MQS JSON, and
HTML reports generated by the pipeline.

MQS grade thresholds: A+ (95), A (90), A- (85), B+ (80), B (75), B- (70),
C (60), D (50), F (0).

## Playbook YAML Schema

Every playbook conforms to `playbooks/playbook.schema.yaml` (JSON Schema Draft
2020-12). Required fields:

- `name`: Unique identifier (`^[a-z0-9-]+$`)
- `version`: Semantic version
- `model`: HuggingFace repo, formats, quantizations, size category
- `test_matrix`: Modalities (run/chat/serve), backends (cpu/gpu), scenario count

Optional sections: `gates`, `oracles`, `property_tests`, `differential_tests`,
`profile_ci`, `trace_payload`, `contract_tests`, `ollama_parity`,
`state_machine`, `kernel_profile`, `metadata`.

## Property-Based Test Generators and Oracles

Property tests use a generator/oracle pattern inspired by proptest:

- **Generator**: Produces random inputs from a domain (e.g., `arithmetic(a: i32, b: i32, op: +|-|*)`)
- **Oracle**: A predicate that must hold for all generated inputs (e.g., `eval(a op b) == parse_int(output)`)
- **Count**: Number of random cases to generate (default 100, max 10,000)

This enables falsification of model behavior without hand-crafted test cases.
If the oracle fails for any generated input, the property test fails, and
proptest shrinking identifies a minimal counterexample.

## Integration with Batuta Pipeline

The `batuta-qa-pipeline.toml` orchestrates 11 pipeline stages:

1. Download -> 2. Convert -> 3. Sanity (G1-G4) -> 4. CPU Qual -> 5. GPU Qual ->
6. Serve -> 7. Chat -> 8. Property Tests -> 9. Stability -> 10. Report -> 11. Certify

Gate IDs in playbooks map directly to pipeline stage gates. The pipeline runner
evaluates gate conditions against actual inference outputs and computes the final
MQS score. Failure policy is configurable: `stop_on_first`, `stop_on_p0`, or
`collect_all`.

## Source of Truth

| Artifact                           | Location                              |
|------------------------------------|---------------------------------------|

## Validation

Validate a playbook against the schema:

```bash
# Check all example playbooks parse correctly
cat examples/*.yaml

# Schema validation (requires a YAML schema validator)
# The schema is JSON Schema Draft 2020-12 compatible
yq eval '.' examples/phi-3.yaml

# Run the full QA pipeline against a model
cargo run --bin apr-qa -- certify --tier full Qwen/Qwen2.5-Coder-1.5B-Instruct

# Quick dim-smoke tier (metadata only, 2-5 seconds)
cargo run --bin apr-qa -- certify --tier dim-smoke state-spaces/mamba-130m-hf
```
